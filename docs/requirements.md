# Requirements and verification register

This register preserves the82 original scientific/infrastructure constraints and adds9 user-requested operational extensions. The full PDF, Appendix H precedence, source module cards and original workflow metadata remain controlling. Listing a module or test does not establish a passed live integration or a scientific outcome.

The [machine-readable register](../spec/requirements_manifest.json) records exact source, implementation, executable test, module-card and diagram mappings. The [module manifest](../spec/module_manifest.json) distinguishes35 original workflows,14 source-derived support modules and9 operational extensions. All58 have existing source, cards, diagrams and executable verification paths.

Local evidence includes explicitly declared fixtures and actual CPU/storage operations. Historical consolidated CPU checks passed. Current documentation/static audits and GitHub reconciliation are recorded in the validation report; current-head full-suite execution and fresh training-state restoration are not claimed. Real model/provider/OAuth/storage/baseline checks are distinct gates. The original statistical method failed. The approved evaluation-only guard passed full actual-frame validation (700/700 jointly covered repetitions); other mandatory training launch gates remain separate. The completed dataset archive and independent 122-artifact/404,000-record Drive audit are verified. Neither62-state experimental results nor future training-artifact persistence are claimed.

Completed source, pairing, eligibility, deficit, protection and Drive requirements carry actual dataset-stage evidence; other machine-readable statuses below retain implementation/full-study gate scope; the completed generation and Drive evidence is recorded separately in [current validation](validation_report.md) and [the audit report](evidence/vllm_sft_drive_readback_audit.json). A pending full-study status does not mean the saved dataset is missing.

Status values mean:

| Status | Meaning |
|---|---|
| `implemented_with_live_dataset_validation` | Actual completed-source/dataset or Drive evidence passed; training and full-study gates remain separate. |
| `implemented_with_local_tests` | Implementation and declared local tests exist; final consolidated audit pending; no empirical outcome claimed. |
| `implemented_with_local_tests_live_validation_pending` | Local implementation/fixture evidence exists; named actual hardware/service/artifact integration remains pending. |
| `implemented_with_local_tests_mandatory_validation_failed` | Local implementation/contract checks exist, but the actual prospective coverage preflight failed; confirmatory launch is blocked. This is not a failed local unit-test claim. |
| `partially_implemented_with_local_tests_live_validation_pending` | Local components exist but a named integration gap remains before actual launch. |
| `implemented_with_local_checks_final_audit_pending` | Executable local audit exists; final static/remote/cold-start reconciliation remains pending. |

The original H100 authorization was followed by separately authorized 14B generation on a supplied Pod. The user provided the 7B rate and reported the 14B stop time. Future spending needs its applicable authorization; independent provider billing certification remains unavailable.
